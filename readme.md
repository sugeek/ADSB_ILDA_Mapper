# Laser Safety Airspace Interdiction System

A Python-based safety framework for real-time laser projection blanking using live ADS-B aviation telemetry. 

Designed to assist Laser Administrators in maintaining strict safety margins for outdoor ILDA projector deployments, this tool provides the necessary programmatic safeguards to support a formal Report of Laser Use. It calculates local Cartesian slant ranges against a defined Maximum Permissible Exposure boundary (NOHD) and dynamically masks the projector's output via OSC.

## Features
* **Real-Time ADS-B Polling:** Ingests local aircraft telemetry data via JSON.
* **Spherical FOV Mapping:** Converts WGS84 coordinates to local ENU, mapping aircraft positions to projector UV texture space.
* **NOHD Hardware Gating:** Drops packets for aircraft safely outside the defined hazard distance (e.g., 3500m).
* **Multi-Platform Support:** Ready-to-use nodes for both MadMapper and Pangolin BEYOND.
* **Fail-Safe Watchdog:** Automatically triggers a master blackout if telemetry data is lost or times out.

## Supported Projection Environments
This system is designed to be hardware-agnostic, providing a unified safety interlock layer for both professional software suites and custom legacy hardware.

| Software/Platform | Driver/Protocol | Primary Use Case |
| :--- | :--- | :--- |
| **MadMapper** | OSC | Modern dynamic projection mapping |
| **Pangolin BEYOND** | OSC | High-end professional show production |
| **OpenLase** | OSC | FOSS / Custom installations |
| **Captain Neon** | UDP/Raw | Legacy hardware / Fixed-function radiators |

*Note: All nodes utilize the same core spatial math and configuration file, ensuring that hazard boundary enforcement is consistent across your entire rig.*

# Usage

1. Testing Environment
Before connecting to live hardware (like an EtherDream DAC), you can test the OSC packet routing locally. Start the mock projector:

Bash
```python mock_projector.py```

2. Running the Safety Node
You must have a local ADS-B JSON feed running on port 8080 (e.g., a dump1090 output). Run the node for your specific software environment:

# For MadMapper:

Bash
```python src/node_madmapper.py --mode mask```
For Pangolin BEYOND:

Bash
```python src/node_pangolin.py --mode mask```
Modes:

--mode mask: Dynamically tracks the aircraft and places a blanking quad over its trajectory in the projection field.

--mode kill: Immediately drops the master opacity to 0% if an aircraft breaches the NOHD limit.

## ADS-B Telemetry Requirement
This system acts as a consumer for a live ADS-B JSON feed. To operate the laser safety nodes, you must provide a telemetry source formatted as `aircraft.json` (the standard output for most dump1090-based decoders).



### Configuring the Data Source
1. **Telemetry Provider:** Ensure you have a software-defined radio (SDR) running a decoder such as `dump1090-fa` or `readsb`.
2. **Endpoint:** By default, the system expects the feed at `http://127.0.0.1:8080/data/aircraft.json`.
3. **Customization:** If your SDR hardware is running on a remote Raspberry Pi or a different network port, update the `adsb_url` field in your `config.json` file:

```json
"system": {
    "adsb_url": "http://<YOUR_ADSB_IP_ADDRESS>:8080/data/aircraft.json"
}
```

## Logging & Auditing
All safety events are logged to `logs/safety_system.log`. 
- **Format:** `YYYY-MM-DD HH:MM:SS,ms [LEVEL] Message`
- **Audit:** The timestamps are generated by the local system clock and can be used as a foreign key to cross-reference against `dump1090` aircraft history logs to verify hazard triggers.
